Phase 1: Code Enhancements & Hardening

1.1 Transaction Safeguards

Critical Compensating Saga for Payment Failures

After bookAppointment transaction commit, emit appointment.pending_payment. A saga orchestrator or the payment service itself schedules a cancellation if no success event arrives within X minutes.

// In AppointmentService.bookAppointment (after session.endSession())
await this.publishEvent('appointment.pending_payment', {
  appointmentId: appointment._id,
  bookingRef: appointment.bookingRef,
  timestamp: new Date(),
});
Critical Idempotent Payment Fulfillment

Store eventId from the payment webhook in a new ProcessedPaymentEvent collection. Check it before processing.

Important Optimistic Locking with version

Add version: Number to Appointment schema. In fulfillPaidAppointment use $inc: { version: 1 } and fail if version mismatch.

Phase 3: Containerization & Production Deployment

3.1 Multi-Stage Dockerfile (Booking Service)

# booking.Dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production && cp -R node_modules prod_modules
RUN npm ci
COPY . .
RUN npm run build booking-service

FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist/apps/booking-service ./dist
COPY --from=builder /app/prod_modules ./node_modules
CMD ["node", "dist/main.js"]
